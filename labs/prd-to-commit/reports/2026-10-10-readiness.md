## 2. 结论

**可以正式切换，作为新需求的默认流程，但带一个观察期。**理由：

- **成本**：小、中需求是 1/10 到 1/20，这个结论稳定。
- **质量**：回放里都不低于历史首轮；真实运行中，PRD 逐字类要求比历史更准。
- **不切换的代价更大**：老系统已经冻结，再并行跑两套没有意义。

**还不能宣称"目标达成"的地方：**

1. **没有一个真实运行拿到提测反馈。**"PRD 明显功能没做"这个核心痛点，只有提测才能证明解决了。PR-02463 和 PR-02208 的提测结果，是第一批硬证据。
2. **Codex 从没跑过这个 skill**，4 个样本全是 Claude。不能当作"两边通用"上线。
3. **大需求的成本还偏高**：PR-02463 用了 124M token、2 小时以上。主要原因是单会话上下文越积越长，加上编码全部串行（并行规则是事后才加的）。

### P2：仓库知识，不进核心 skill

放到 skill 下的 `references/fameex.md`，按需读：
- zh-CN 专用命名空间要登记到 `ZH_CN_SOURCE_ONLY_NAMESPACES`
- MSW 需要在 proxy 的 `LOCALE_BYPASS_PATTERNS` 里放行
- 登录态浏览器验证的做法：假 token，加 playwright 拦截无关接口

长期看，这些应该沉淀进 fameex-web 的 `AGENTS.md` 或 `.cursor/rules`（团队文件，需要你决定）。

### 暂不做（只出现过 1 次）

- 相互依赖的配置行要先推演可行性
- 改动文件里的存量 lint 债由谁处理
- 子 agent 不跑 git 只能靠自觉

## 4. 切换为正式的步骤

1. **修 P0 和 P1**（约半天），然后回放 PR-01930 做回归：得分不低于 14/15，墙钟不超过 35 分钟。
2. **版本化**：`~/.ai-rules` 目前不是 git 仓库，skill 改了也追不回来。改成 git 仓库，打 `prd-to-commit v1.0` 标签；每次改 skill 都要附回放结果。
3. **切换入口**：
   - docs_tdd 的 `AGENTS.md`、`common/rules/rule-router.md`、`startup-prompt.md` 目前仍指向 Web Lite，改成指向 prd-to-commit，Web Lite 标记为已废弃。
   - docs_tdd 和 auto_pilot 的 README 顶部加"已冻结"说明。
4. **Codex 验收**：用 Codex 跑一次（回放 02306 就够，约 10 分钟），确认脚本、子 agent 冷读和并行在 Codex 上也能走通，再宣称两边通用。
5. **观察期**：接下来 5 个真实需求，每个记录提测缺陷，分为"PRD 写了没做 / 理解错 / 后端 / 视觉"，加上 stats 数据。达标条件：
   - "PRD 写了没做"类缺陷平均 ≤1 个/需求；
   - 中小需求 ≤30M token、≤45 分钟。

   达标即结束观察期；出现同类问题 2 次，按规则修改并回放验证。
6. **收尾，看你决定**：
   - fameex-web lint-staged 里的 docs-tdd v2 guard、全局规则里的 `DOCS_TDD_COMMIT_MODE` 一行，可以在存量 v1/v2 项目全部收尾后删除。
   - lark-bot 目前仍走 docs_tdd 引擎，单独评估，不在本次切换范围内。
