## 效率与成本

- 干净跑（不中断）：小需求 6–16M token、19–41 分钟（PR-02306 6.3M / 19 分钟，PR-02022 15.6M / 41 分钟）；中大需求 45–90M token、50–90 分钟，含冷读与全页面浏览器验证。
- 省 token 的改动：读图和找代码落点交给子 agent，只交回摘要；子 agent 用 Opus、评分用 Sonnet；冷读与浏览器结果写盘，中断后从文件续，不再整轮重做。
- 本机限制：16G mac 同时最多 4 个 dev server（`dev.mjs` 自动排队，`~/.config/prd-to-commit/dev/max-dev` 可调）。

## 这一轮改了什么

规则（每条都由回放复现或来自全局规则）：

- 读图转写、编码前看原图；落点地图；同因搜索含被替换的展示字段；新功能不泛化到其他对象。
- 待确认≠不做；显隐条件完整实现；「已兼容」须代入数值核实。
- 冷读与浏览器验证两个独立子 agent 同时跑，结果写盘；都回来才改代码。
- 埋点参数写纯函数并单测断言取值；PRD 列了展示名就做码→展示名映射；不按展示文案反推类型。

工具：

- `check.mjs` 能拦服务端组件误引 hook（运行时 500）和 Vue2 旧工程不支持的语法。
- `dev.mjs` 全机限流，并自动修正 worktree 里装错版本的 heroui；停服时还原 dev 改写的文件。
- `auth-fallback.mjs` 无人值守假登录；`browser.mjs` 在 dev（pfyys）上默认真实写入（报告 `realWrites` 列出、交付说明写明改了哪些 dev 数据；spec 设 `strictWrites` 可拦截），发往其他环境的写操作与登出一律拦截。（2026-10-20 更正：原文写「写接口一律拦截，不会写 dev 数据」与实现不符。）

完整清单见 [releases.md](../releases.md) v1.6 节，逐轮数据见 [iteration-ledger.md](../iteration-ledger.md)。

## 剩余风险

1. **PR-02074 方差**：各轮 10–12/14，每轮丢的检查点不同（「更多结果」出现条件、question 字段口径等，PRD 本身没写清）。属于 PRD 模糊，不是规则能解决的。
2. **中断会降低质量**：R17 中断续跑的 02022 只有 9/12、02306 只有 6/7，干净重跑回到 12/12、7/7。v1.6 已让冷读和浏览器结果写盘，暂停续跑实测正常（R19 四个都是暂停后续跑，均不低于基线），但尽量避免长时间中断。
3. **后端未定的字段与码值**：skill 会用明显非法的占位（如 `'-1'`）并列在交付说明「上线前必须替换」，联调前必须替换，否则功能不生效。
4. **观察项**（各出现 1 次，未改规则，再出现即立规则）：写操作后刷新数据与「靠缓存判断是否弹窗」冲突；采纳冷读建议前未对照 PRD；PRD 少写校验条件时提示怎么补。见 releases.md 观察清单。

## 怎么用

新需求在 fameex-web 里直接说：

```
用 prd-to-commit，项目号 PR-xxxxx，PRD：<Lark 链接>
```

流程会先给出需求清单、待确认和计划，确认一次后自动做到本地 commit（不 push）。交付说明里会列出提交 SHA、上线前必须替换的占位、待确认项、冷读和浏览器验证的发现，以及哪些检查没覆盖。
