## 5. 偏离 skill / 规则不清 / 工具问题

1. **远端分支检查太晚**：worktree.mjs 才发现远端已有 `feature/PR-02418`，此时 PRD 已拉完、已读完。用户反馈：开始前先查远端干净。→ 候选：SKILL §1 第 0 步 `git ls-remote origin 'feature/<ID>*'`，或 fetch-prd.mjs 顺带检查。（已存用户记忆。）
2. **同事产出污染**：远端分支里有同事的 openspec，主会话顺手当契约读了。→ 候选：远端已有分支时，其内容不得作为 inputs，除非用户指定。
3. **规则 G「严格 enum 放宽」在 Effect Schema 下成本高**：web-next 的 `Schema.Enum` 放宽会把类型扩成 string，牵动多处穷举 switch；本次只加占位成员、没放宽，记为风险。zod 侧（web 合约）放宽了，但放宽后未知值显示了原始 i18n key，靠浏览器才发现。
4. **「沿用现状」与「PRD 明写文案/精度」冲突时的优先级没写**（X1、M2 两次，同一需求内）。
5. **修复阶段的同因搜索**：§8 写了同因定义，但主会话修 X1 时只改了冷读点名的 4 个文件，第 2 轮冷读才补出财务审计。
6. **截图标注色 ≠ UI 色**（M5）：S2 子 agent 与主会话都按 asset-25 的红字实现，冷读 R2 用 asset-23（下拉选项也是红字）反证。
7. **run-log 时间戳**：主会话有几行写了估计时间（「~21:00」），实际时钟是 20:5x，事后更正。→ run-log 一律用 `date`。
8. **浏览器 R1 耗时**：绕开登录后每个页面都要 mock 用户态与后台 menus/权限，5 个站点 51 分钟、210 次工具。冷读早 40 分钟返回后主会话只能等（skill 规定两者都回来才改）。
9. **存量失败**：admin `useBusinessTypes.test.ts` 1 例（mock 缺 `AccountTypes.finance`），与本次无关；check.mjs 只跑改动测试所以没受影响。
