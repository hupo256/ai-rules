## 暴露的 skill 问题（未修，待迭代）

1. **fetch-prd 静默丢掉嵌入的电子表格**：PRD 里有 3 个 `<sheet>`，`meta.failed` 却是空的。改法：识别 `<sheet token sheet-id>`，用 `lark-cli sheets +csv-get` 导出到 `sheets/`；导不出来的写进 `failed`。这次是我手动补拉的，内容全是后端字段，所以没影响结果。
2. **check.mjs 对 legacy-admin 给出假通过**：biome.json 忽略了 `apps/*/legacy-admin`，tsc 也不覆盖 JS 和 Vue2，结果「pass」其实什么都没查。改法：
   - 识别出 legacy 文件时，报告 `not-covered`，不再报 pass；
   - 并补跑三项：JS 文件用 `node --input-type=module --check`，Vue 文件用 `@vue/compiler-sfc` 编译模板，改动范围内的 `*.test.js` 用 vitest 跑。
   这三项这次是我手动跑的。
3. **worktree.mjs 只检查本地分支**：远端已有同名分支 `origin/feature/PR-02208` 时不会警告，而且脚本不支持自定义分支名。改法：检查 `origin/<branch>` 是否存在并警告；增加 `--branch` 参数。
4. **清单和冷读模板里没有「接口契约 / 附件」的位置**：PRD 不带契约时，只能在 §3 临时问。冷读提示也是我手工加了契约路径和 sheets 路径。改法：在 §1 加一个可选输入 `api-contract`（文件或 YApi），冷读模板加上 `<额外输入>` 占位。
5. **相互依赖的配置行，默认方案没做可行性推演**：清单阶段定的「单行编辑 + 整体校验 + 不联动」是死路，任何边界调整都存不了。这是写单测时才发现的，§3 用户确认没能拦住。改法：§2 加一条，区间、阶梯、档位这类相互依赖的行，要推演一遍「改一个边界」能不能保存成功。
6. **后台新页面放在 legacy 还是 Next，skill 没要求核实**：仓库 `AGENTS.md:83` 写到「从 legacy 进入 Next 页面」这种模式，历史实现两套都做了。本次只看了近期提交（全部在 legacy），就判定做 legacy，判断依据偏弱。**用户已定规则（2026-10-10）**：同级、兄弟页面在哪个工程，新页面就放哪里。按这条规则复核：「合约配置」的兄弟页面都在 legacy 的 `router/marketManagement.js`，Next 的「期貨管理」是另一套菜单，所以本次放置正确；历史实现在 Next 里又做一套，不符合规则。改法：§2 找落点时，先定位兄弟页面的路由文件再决定工程。这条是候选规则，按「同类错误出现 2 次、回放能复现才加」的约束，暂时不写进 skill。
