# prd-to-commit v1.8 迭代计划（2026-10-31）

依据：v1.7 发版后的全面复盘——8 个真实需求（[real-runs/](../real-runs/)）、3 份人工对照、1 份提测 bug 对照（PR-02634）、R20/R21 五次回放的执行方反馈。
纪律不变（[README](../README.md)）：规则 ≥2 次且可回放复现才改；工具/文档按实测放行；SKILL 常驻 ≤18.4K、细则在 references、每条规则一处。

## 1. 复盘结论

### 1.1 质量：PRD 覆盖已不是短板，三类差距都在 PRD 之外

| 差距 | 证据 | 现状 |
|---|---|---|
| **目标工程选错** | 3/3 从零需求与同事不同（01549、02634 在 web-next；02012 独立应用） | v1.7 加了判定规则 + fameex.md 判据，**但没有任何回放验证过**（R20 四个基准的 scope 都限定了工程） |
| **契约猜测** | 02634 字段 74%、路径 0/4、错误码 0/5；02012 路径 3%；01507 码值全占位 → 联调前功能整体不可用 | v1.7 加「镜像契约整份照搬」；仍没解决「PRD 无契约」的根本——§3 问用户要契约只是一句话，直接做模式下没有任何动作 |
| **隐含需求** | App WebView（02634）、未开始置灰（02634 对照 + QA bug 7986）、返回刷新（02634）、已成交上限（01549）、配置表写死（02634 QA 7994） | 只进了 fameex.md；活动类需求的共性（未开始/已结束按钮、配置以接口为准）可沉淀成「活动页」小节 |

实战效果：**我们自己的产出还没有一个进过 QA**。PR-01723、PR-02374 待提测；其余 6 个是对照用。唯一的真实 bug 数据是同事版 02634（8 条有效：我们能避 4、会踩 1、换形式踩 1）。结论「PRD 内的状态/行为我们稳，PRD 外的要靠经验」在 1 个样本上成立，需要自己的提测数据验证。

### 1.2 效率：成本花在哪里没有数据

- 单需求 31M–372M token、12 分钟–3.6 小时；5 个并行跑时 agent 自身只占 10–20%，其余在子 agent。
- **stats.mjs 只给总量**，不按阶段（读图 / Explore / 编码 / 冷读 / 浏览器 / 修复）拆分，无法回答「哪一步最贵、值不值」。已知的只有：浏览器在大需求里是关键路径（02012 R1 约 2 小时；02418 51 分钟），冷读 R1 一次 400–525k。
- v1.7 的「按站点并行浏览器」「prewarm」还没在多站点需求上验证过。

### 1.3 流程与工具：重复手工动作

| 动作 | 这两天做了几次 | 现状 |
|---|---|---|
| 启动一个实跑（preflight → fetch → worktree → 写 prompt → 派 agent） | 8 | 模板在 `~/.prd-cache/_runs/real-run.tpl`（不在仓库里），每次手改 |
| 人工对照同事分支 | 3 | `compare.tpl` 同上 |
| 拉 QA bug 表并对照 | 1（以后每个提测需求都要） | 手敲 lark-cli，字段/附件下载要试错 |
| web-next 偏移端口假登录 | 2 次回放都自己摸索（R20/R21-01507） | auth-fallback.mjs 只有 apps/web 的配方 |

### 1.4 回放执行方反馈（R20/R21，按次数）

- 2 次：browser.md 缺 web-next 假登录配方；「码值全占位 → 功能联调前不可用」应在交付首行强调。
- 1 次：§8「范围外收窄」与「不按文案反推类型」碰头无裁决顺序；PRD 只给一页文案时同规则其他页是否统一；存量未格式化文件冷读前要不要先 `--write`；fameex.md「只写 zh-CN 新命名空间」两节口径冲突；§1 转写子 agent 派发早于读 delegation.md（已改措辞）。

## 2. 改动清单

### 阶段 A：工具（实测放行）
- A1 **stats.mjs 按阶段拆分**：子 agent 按首条任务提示归类（读图/Explore/编码/冷读/浏览器/修复/对照/其他），输出「阶段 × token × 次数 × 时长」表；`--until <时间>` 排除跑完后的对照/评分 agent。先对 8 个实跑 + 5 个回放跑一遍，产出成本分布（S7 的输入）。
- A2 **`bugs.mjs <ID>`**（新）：从 EX 项目 bug 统计表拉该需求全部 bug（按项目ID contains），落 `~/.prd-cache/<ID>/bugs/{raw.json,bugs.md,img/}`，bugs.md 每条一行（编号、端、标题、归因、状态、截图路径），供提测后补录与对照。
- A3 **`launch.mjs <ID> <lark-url> [--offset n] [--mode direct|confirm]`**（新）：串起 preflight → fetch-prd → worktree → 生成 agent prompt（模板进仓库 `scripts/run-prompt.tpl`，含公平性与并发约束），输出 prompt 路径；preflight 非 0 时停下并打印结论。人工对照模板也进仓库 `labs/.../replay/tools/compare-prompt.sh`。
- A4 **auth-fallback.mjs 加 web-next**：`webNextFakeLogin(page, …)`（`localStorage.dev__accessToken` + mock `user_info_v1`），browser.md §2 写明；2 次回放各自摸索过。

### 阶段 B：参考文档（自审放行）
- B1 **fameex.md「活动页」小节**（新）：行动按钮未开始/已结束都置灰（PRD 常只写结束；02634 QA 7986）；奖池档位、比例等配置接口有同类字段时以接口为准、PRD 表只作缺省（02634 QA 7994）；App WebView 小节并入或互链。
- B2 **fameex.md i18n 口径**：「新建只有 zh-CN 的命名空间」统一为 web-next 可新建（登记 namespaces.ts）、apps/web 用 `ZH_CN_SOURCE_ONLY_NAMESPACES`，旧代码没有该机制才不新建。
- B3 **交付说明模板**（SKILL §10 一句）：占位码值导致联调前整体不可见的，首行写明「联调前不可用」（2 次）。

### 阶段 C：验证目标工程规则 + 积累自己的实战数据
- C1 **新增 2 个回放基准**：PR-01549、PR-02634（base `f9309e9fe0`，PRD 快照已在 `~/.prd-cache/PR-*/r*`），评分标准以同事最终分支 + PRD 为依据，**陷阱 T1 = 目标工程选错（未落在 apps/web-next）**，C 系列取 human-compare 里双方一致/同事更贴的行为。scope 不限定工程（否则验不到 C2 规则）。
- C2 **回放 R22**：两个新基准各跑 1 次，看目标工程判定是否生效、浏览器按站点并行是否触发（02634 有 PC+H5 两套 spec，单站点）。
- C3 **自己的提测数据**：PR-01723、PR-02374 提测（push/MR 需用户授权）→ QA 后 `bugs.mjs` 拉取 → 归类到 real-runs（这是「实战效果」唯一的直接证据）。

### 阶段 D：效率
- D1 用 A1 的阶段成本表写一页分析（`reports/2026-10-31-cost-breakdown.md`）：按阶段的中位数/最大值、墙钟关键路径、与得分的关系；给出 ≤3 条可执行的降本候选（只列，不改规则）。
- D2 若 C2 的 02634 回放显示浏览器仍是关键路径，把「截图只看失败步与每页 1 张」「spec 先写后跑」等 browser.md 已有要求写进浏览器子 agent 的派发提示（delegation.md）。
