## 2. 改动清单（按阶段）

### 阶段 A：工具（无需回放，逐项实测放行）
- A1 **`scripts/preflight.mjs <ID>`**（新）：`git ls-remote` 列出含该编号的远端分支并判断是否已合入 online（`merge-base --is-ancestor`）、base 历史里是否已有该需求提交、本地 worktree 是否存在；输出「干净 / 远端有在途分支 / 已合入 online（复核补缺模式）」三种结论。解决 #11、#21、#4 的发现环节。
- A2 **fetch-prd.mjs**：下载 `<figure><source name token>` 附件到 `inputs/`（lark-cli `--output` 只认相对路径，脚本内 cwd 到目标目录），meta.json 加 `attachments`；下载失败列入 `failed`。解决 #10。
- A3 **stats.mjs**：匹配改为「用户消息（不限前 5 条）或任一事件文本中出现 `~/.prd-cache/<ID>` / `~/github/<ID>` 路径」且按首次/末次出现时间截取区间；子 agent 文件按时间区间归入。解决 #9。
- A4 **dev.mjs**：legacy 站点 `prewarm` 子命令（只做 npm install，不启动），供多站点需求在编码期预装。解决 #2 的一部分。
- A5 **browser.md / scripts 文档**：后台免登录（mock menus/权限/adminLogInfo + localStorage token）写成固定做法并给 helper 位置；SendMessage 续跑 usage 为累计值；跨时间边界断言留 ≥8s 首屏；多站点拆分建议（见 C6）。解决 #12、#18。

### 阶段 B：参考文档（无需回放）
- B1 **fameex.md**：
  - 「工程归属」补 C 端判定数据：apps/web vs apps/web-next 近期活跃面（合约、活动页新页在 web-next；资产/账单仍在 web）、独立应用先例 `apps/business-system`；判定方法（online 近 2 月该模块提交数、首页入口所在工程、同模块在途分支）。
  - 「运行时坑」补 React 19：App Router 实际运行 React 19，`findDOMNode` 类库（react-quill）挂载即崩，antd 静态 `message/Modal` 不渲染，用 `@/utils` 的 message / hooks 版；写接口的组件若依赖 `Form.useFormInstance()` 必须在 Form 内。
  - 新增「App WebView」小节：原生分享 `showShare`、返回页刷新（pageshow/visibilitychange）、客服浮窗隐藏、App 登录态；PRD 出现「App 端/两端验收」时清单展开这些行。
  - MSW：base 无基建且不能引入时，用浏览器 spec mocks，记 `not-required`；权限 key 未知用 `null`（不拦截）而非非法占位；legacy 缺 i18n key 显示空白（只改 zh_CN 时要确认 fallback）。
  - 错误码：仓内 `errorCode.json` 为同因落点，「同下单提示」类需求复用下单侧映射。
- B2 **browser.md**：A5 的内容。

### 阶段 C：SKILL.md 规则（先做架构拆分，再改；需回放）
- C0 **按阶段拆分，不做无脑压缩**（用户 2026-10-30 意见：上限若影响质量就从架构上解决）。18KB 上限是 10-09 审计定的自律限制（防规则膨胀），不是平台限制。做法：SKILL.md 只保留流程骨架、各阶段触发条件与「先读 X」指针（常驻 ≤18KB），细则按阶段拆成按需加载文件、每条规则只在一处：
  - `references/checklist-rules.md`：§2 全部清单规则（现有 + C2–C5 新增）；
  - `references/delegation.md`：§3.5 子 agent 派发规则（现有 + C7）；
  - `references/coldread-prompt.md`：§7 冷读提示词全文（SKILL 只留 `<BASE>`、`add -N` 与一行指针）；
  - fameex.md、browser.md 不变。
  风险「引用文件没被读 → 规则失效」：阶段入口用强制措辞（「进入 §2 前先完整读 …」），并由 D1 回放验证（得分不低于 v1.6）。
- C1 **§0 预检**（新，放 §1 前）：`node $S/preflight.mjs <ID>`；远端有在途分支 → 停下问用户（是否以其契约层为准、分支名）；已合入 online → 「复核补缺」模式：清单每行先核 base 现状，已满足写「已兼容」，冷读提示声明「行为可能已在 base 实现」。（#11、#4、#21）
- C2 **§2 目标工程判定**（新，找落点前）：同业务在 ≥2 个工程/应用有实现、或 PRD 写「独立系统/新站点」时，用 B1 的判定方法定目标；定不了作为**阻塞问题**问用户（直接做模式写在交付说明首行）。（#1）
- C3 **§2 接口占位**：有同类契约时整份照搬全部字段只换业务段；「沿用 X 接口命名」须逐字段抄全；搜仓内语义相近的真实接口列候选；权限 key 未知用 null。（#3、#19）
- C4 **§2 优先级一句**：PRD 明写的文案、精度、字段名优先于「沿用现状」「后端直出」。（#6）
- C5 **§2 清单粒度 + 同因**：一句含多个可验收动作拆成多行；新增枚举值/审批来源要搜其他端的解析点与筛选项；错误码映射按同因复用。（#16、#14）
- C6 **§6 浏览器**：站点 ≥2 时按站点派多个浏览器子 agent 并行（各自 `P2C_PORT_OFFSET`），legacy 站点在编码期 `dev.mjs prewarm`；截图只看失败步与每页 1 张。（#2）
- C7 **§3.5 子 agent**：派编码子 agent 的提示附 §2 的占位/枚举/i18n 规则；子 agent 不自跑 tsc（主会话合并后统一 check.mjs）；并行子 agent 的 i18n 新 key 写草稿文件由主会话合并；run-log 时间一律 `date`。（#15、#7、正面做法）
- C8 **§8 措辞**：第 2 轮冷读与浏览器复跑都返回后再改；第 2 轮修复后只对运行时类问题再复跑一次，不开第 3 轮冷读；修复时也做同因搜索。（#13）
- C9 **§5 MSW**：base 无 MSW 基建且不能引入基建提交时，不加 MSW，mock 写在 spec。（#8）
