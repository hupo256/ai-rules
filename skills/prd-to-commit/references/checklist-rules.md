# 需求清单规则（SKILL §2 用，进入 §2 前完整读一遍）

清单表头、「一个页面一行」、端的取值、目标工程判定在 SKILL §2；这里是每一行怎么写、落点怎么找的全部规则。每条都来自真实运行或回放。

## 行怎么写

- 核对后现状已满足、无需改代码的行，落点写「已兼容：<文件:行> + 一句理由」。理由要对照 PRD 的具体要求逐项成立（要读的字段代码确实在读；等式在展示精度下成立，如分项各自取舍后再相加），不能只是「已有类似逻辑」；涉及等式/精度的代入数值算一遍。冷读对这类行按 PRD 原句复核并代入数值。
- **一句 PRD 含多个可验收动作时拆成多行**（「支持复制、删除和拖拽排序」是 3 行），不按句子建行；否则子 agent 做一半、冷读才补出（PR-02374）。
- 删除线、「本期不做」只按 PRD 原文判断，不自行推断。拿不准的，标 `?` 放进待确认。
- 依赖后端的字段：写出接口名或字段名；未知就写「待确认」，**不要编造字段**。后端口径不明的地方列进待确认。
- **列待确认（或称阻塞）不等于不做**：前端能独立做的部分照 PRD/契约最可能的读法实现（契约或接口文档写明的字段直接用；提示/Toast 没给文案就复用仓内同类文案或自拟；严格 enum 会让后端新值整体解析失败的就放宽），待确认只记风险。
- **PRD 明写的文案、精度、字段名优先于「沿用现状」「后端直出」**：PRD 给了具体文案或小数位就照写，不以「现状如此」为由保留旧值（PR-02418 M2/X1 两处）。
- PRD 写明的显隐/出现条件（「有数据才显示」「超过 N 条才出现」）记进清单，按原文完整实现，不能只判一半或无条件渲染。
- 需要某个口径值（如「只含普通体验金的可用额」）时，**先在 schema/类型里搜现成字段**（如 `normalXxx`、`xxxExclude`、`availableXxx`），有就直接用，没有才列待确认；不得用兄弟字段做减法、求和去推算，也不得按展示文案/i18n label 反推类型（仓内已有此写法也不沿用；能用金额正负等契约字段区分就用），标待确认也不行。PRD 明文给的公式（如「使用中 = 冻结 + 占用」）照公式实现。
- 字符串渠道名/类型名（如 `Telegram`）仓内同类值已有固定写法且被严格解析的，沿用该写法并列待确认，不用非法占位（否则解析整体失败）；仓内已有**语义完全相同**的错误码/枚举（PRD 写明沿用现有逻辑）时直接复用，不另设占位。错误码按同因复用：「同当前下单时的提示」类需求复用下单侧映射，写接口按同业务前缀搜 `errorCode` 文案表里的已有码分支（`references/fameex.md`「口径与错误码」）。
- 枚举码、流水类型码不能按约定去猜：列待确认，§3 问用户要。给不出时值用明显非法的占位（如 `'-1'`，不按现有码顺延），标 `TODO(<ID>): 待后端确认`，占位集中在一个文件并在交付说明列出。**多值枚举每个值各用不同占位**（`'-1'`/`'-2'`/`'-3'`），否则分支区分不开。PRD 列了展示名（如平台名）时建「码→展示名」映射，不直出。接口路径/字段未知时同理，集中在一个 service 文件逐项标 TODO，业务逻辑照 PRD 写全。**例外：权限 key 未知用 `null`（不拦截）**，非法占位会让所有用户无权限（PR-02254）。
- **接口占位镜像同类契约时整份照搬**：仓内有同类真实契约（同业务的上一期、同形的另一个榜单/订单接口）时，占位接口照搬它的全部字段、分页与错误码，只换业务段的路径与名字，不按本期 UI 用到多少裁剪（PR-02634 裁剪后命中 74%，整份照搬可达 97%）；PRD 写「沿用 X 接口命名」时逐字段抄全 X（PR-01549 漏了 6 个 `order_create` 现成字段）；先搜仓内语义相近的真实接口列为候选契约，写进待确认。
- PRD 文字和原型图冲突时，以文字为准，并把冲突列进待确认；文字没写而原型画了的层级、布局按原型做，不算冲突；但正文已列举某处的按钮/操作时，原型多出的控件（如 ×）算冲突，以正文为准。PRD 内部自相矛盾时（如方案章节 vs 验收用例/附录），**以产品方案正文（含删除线）为准实现**（正文小节之间不一致时各按各的），矛盾列待确认，不因矛盾退回现状。
- 规则提示/勾选清单必须与提交校验一致，不能「提示全部通过、提交却被拒」。PRD 文案少写某个校验条件时列待确认，并让显示与校验一致（并入已有提示项或补一行）。用新提示替换旧提示时，旧提示写明的条件（如「含数字」）新提示里也要能看到。
- 开关/表单初值来自服务端（自动申购、通知设置等）时，加载中或失败不得当「默认开启/关闭」提交，按 `coding-quality` → `references/controlled-form-hooks.md`「Unknown is not unset」处理（PR-01507 实跑与回放两次踩 T2）。
- 收紧或改变校验规则（密码、格式、长度等）时，把用到它的入口分成两类：**设置新值**（注册、修改、重置）套新规则；**验证已有值**（登录、校验旧密码、二次验证）保持宽松或只做非空，否则存量用户被锁在门外。
- 语言文件按仓库规则（FameEX Web 只改 zh-CN），其他语言不同步时清单注明依据。

## 落点怎么找

- 后台**新增页面**放在同一菜单分组的兄弟页面所在的工程（先找兄弟页面的路由文件），注册点（路由、菜单配置、权限）照兄弟页面一样登记。不要 legacy 和 Next 两套都做，也不要篡改后端菜单接口的返回数据。只有兄弟页面本身分布在两个工程时，才列进待确认。
- 找落点时，「后台/管理端」的页面要连 Vue2 旧工程一起搜（FameEX：`apps/admin/legacy-admin`、`apps/futures-admin/legacy-admin`）。只有搜过这些目录仍找不到，才能写「本仓无此页面」，并附上用过的搜索词。
- 单工程且落点 ≤10 处时主会话直接搜；否则先派 1 个 Explore 子 agent（跨 ≥3 个工程时每工程一个）：给它清单草稿行，要它返回落点地图（文件:行、≤3 行片段、同因拷贝）。据此填落点，之后**只读要改的区段**，不整篇读 >150 行的文件，读过的不重读；多段/多文件**合在一次调用里读**。
- 每条都要做**同因搜索**：同一常量、正则、枚举、组件、文案 key，以及**被删除/替换的展示字段**（如 `tagLabel`），在仓内的所有拷贝、调用入口和渲染点（含写死的字面量副本）。i18n key 扁平与嵌套写法都要搜。**本次新增的枚举值/审批来源/类型也算同因**：搜其他端的解析点（严格 enum、legacy 下拉）与筛选项，一起加（PR-02374 AGENT_UID、PR-02012 审批业务类型）。
- FameEX 已知坑（工程归属、App WebView、口径与错误码、i18n 登记、MSW、运行时坑、图标查找等）见 `references/fameex.md`，碰到相关改动时再读。
