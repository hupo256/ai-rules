# 分批与子 agent 派发（SKILL §3.5、§6 用，写 plan.md 前完整读一遍）

## 分批

- **批次 0（主会话串行）**：先定下所有步骤都要用的契约，包括类型/schema、service 接口、路由与路径常量、i18n 文件和 key 骨架、共享组件的 props。只有后面还要派并行子 agent 时，批次 0 写完先把共享 query/类型接进一个仓内目标组件的最小调用点，再跑一次 check.mjs 锁定契约；串行时直接放到 §6 一起查。不依赖契约的零散步骤和批次 0 同时开工。
- **能否并行看依赖**：两批互不改同一文件、只依赖批次 0 已定的契约、不需要对方的产出，才算可并行；否则排成先后批次。
- **值不值得派看工作量**：可并行的批次里，只派工作量明显大于子 agent 重建上下文成本的（如另一个工程、独立页面）；零散小改动主会话顺手写。没有值得派的就全程串行。
- **值得派的有 ≥2 批时**，主会话只做批次 0、合并和验证，不写大段 UI；只有 1 批时派它出去，主会话写主线。

## 编码子 agent 的提示要带什么

- 每步一个子 agent：清单行原文、可写文件清单（越界只读）、契约文件路径、§5 编码规则。共享组件写明只允许做什么（如「只加可选 prop」）。
- **把 `references/checklist-rules.md` 里涉及它那几行的规则原样附上**，至少：占位用明显非法值且多值各不同、权限 key 用 null、新增枚举要同步其他端、文案逐字照 PRD、只改 zh-CN。只写在主会话层子 agent 看不到（PR-02012 子 agent 把占位写成看似合法的值）。
- 不跑 git（删文件用 `rm`）、不跑全量检查、**不自跑 tsc**（临时 tsconfig 的「范围 tsc 0 错」不可信，PR-02374 七个子 agent 全部自报 0 错、合并后 check 仍抓到 2 个），类型问题由主会话合并后统一 `check.mjs`。
- 并行子 agent 不直接改同一份语言文件：各自把新 key 写到 `~/.prd-cache/<ID>/i18n-draft-<步骤>.json`，主会话合并进语言文件（PR-02374 61 key 0 冲突）。
- 返回改了哪些文件和未决问题。这一批都返回后**逐个看 diff 合并**（报告可能与改动不一致），再开下一批。

## 浏览器子 agent 的提示要带什么

- 给它清单、`media-notes.md`、`git diff <BASE>`、`references/browser.md`，要它按清单每个页面/入口写 spec 跑（接口没好就在 spec 里 mock），返回问题列表、spec 路径和 not-covered 项，不改业务代码；截图与断言的取舍按 browser.md §4。
- **站点 ≥2 时每个站点一个浏览器子 agent，同时派**，各自 start/stop 自己的站点（受 `dev.mjs` 全机限流，起不来先写 spec）；不要一个子 agent 串行跑多个站点（PR-02012 浏览器 R1 约 2 小时）。本次任务被限定只能起 1 个 dev server 时（回放并发约束）才退回 1 个子 agent 按站点串行。
- 用户不在场（直接做、回放）要写明：`auth = false` + mocks（后台用 `auth-fallback.mjs` 的 `fakeAdminLogin`），`strictWrites = true`，不要请求登录。
- 被 SendMessage 续跑的子 agent 再次报告的 usage 是**累计值**（含上一段），汇总成本只记最后一次，不要相加（PR-01549、02634、02127 三次重复计）。

## 冷读与浏览器同时派

- §6 静态检查通过后，冷读子 agent 与浏览器子 agent 同时派出（浏览器后台先派，再前台派冷读；都不改业务代码，结果先写入 `~/.prd-cache/<ID>/coldread-N.md`、`browser-roundN.md` 再返回，中断后读文件续）。
- 子 agent 没有「等待」原语：主会话等报告文件出现再读，不要轮询式反复 SendMessage。

## run-log

`~/.prd-cache/<ID>/run-log.md` 记每批起止时间、返工原因和意外。时间一律用 `date` 命令的输出，不写估计值（PR-02418、PR-02374 两次写估计时间后无法复盘）。
