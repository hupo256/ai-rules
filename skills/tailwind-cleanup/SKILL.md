# Tailwind 自定义值清理

消除项目中的 Tailwind 自定义值（`[123px]` 语法），替换为标准类名。

## 执行步骤

### 1. 扫描自定义值

```bash
grep -rn "\[.*px\]" src --include="*.tsx" --include="*.ts" | grep -E "className|class=" | wc -l
```

查找所有使用方括号自定义像素值的地方。

### 2. 分类处理

#### 🟢 可以清理的（优先级从高到低）

##### A. 完全匹配标准值
直接替换为对应的 Tailwind 类：

| 自定义值 | 标准类 | 计算 |
|---------|--------|------|
| `h-[100px]` | `h-25` | 100 ÷ 4 = 25 |
| `w-[160px]` | `w-40` | 160 ÷ 4 = 40 |
| `h-[112px]` | `h-28` | 112 ÷ 4 = 28 |
| `min-h-[420px]` | `min-h-105` | 420 ÷ 4 = 105 |
| `gap-[2px]` | `gap-0.5` | 2 ÷ 4 = 0.5 |
| `w-[3px]` | `w-0.75` | 3 ÷ 4 = 0.75 |

**Tailwind 单位换算**：1 单位 = 4px

##### B. 使用最接近的整数值
当精确值不是 4 的倍数时，使用最接近的整数（±1-2px 误差可接受）：

| 自定义值 | 接近值 | 标准类 | 误差 |
|---------|--------|--------|------|
| `w-[90px]` | 88px | `w-22` | -2px |
| `w-[215px]` | 216px | `w-54` | +1px |
| `w-[138px]` | 136px | `w-34` | -2px |
| `h-[173px]` | 176px | `h-44` | +3px |

**原则**：视觉差异微小 > 代码清晰度

##### C. 使用语义化类名
检查 theme 配置，使用预定义的语义类：

| 自定义值 | 语义类 | 说明 |
|---------|--------|------|
| `text-[10px]` | `text-meta` | 检查 theme.css |
| `text-[14px]` | `text-sm` | sm = 14px |
| `text-[16px]` | `text-base` | base = 16px |
| `text-[20px]` | `text-xl` | xl = 20px |

#### 🟡 需要保留的（必须注释说明）

以下情况保留自定义值，但**必须添加注释**说明原因：

1. **精确布局定位**：
   - Hero 区绝对定位：`bottom-[185px]`
   - 渐变遮罩位置：`h-[200px]`
   - 内容区精确对齐

2. **设计稿精确尺寸**：
   - 卡片组件尺寸：`h-[152px] w-[210px]`
   - 封面高度：`h-[105px]`

3. **Grid 模板列**：
   - 固定宽度侧栏：`grid-cols-[1fr_340px]`

4. **基座/容器宽度**：
   - 最大宽度约束：`max-w-[1600px]`

5. **精确行高**：
   - 设计稿指定：`leading-[21px]`

6. **特殊布局**：
   - 负边距调整：`-mt-[50px]`
   - 自定义断点：`min-[1600px]:mt-0`

**注释格式**：
```tsx
{/* Hero 区精确定位（设计稿）：底部 185px 处 */}
<div className="bottom-[185px]">

{/* 卡片尺寸来自设计稿：152×210 */}
<article className="h-[152px] w-[210px]">
```

### 3. Tailwind 数值支持规则

**✅ 支持的值**：
- 任意整数：`w-22`, `h-44`, `min-h-105`
- 0.x 小数：`w-0.5`, `w-0.75`, `gap-0.5`
- x.5 小数：`size-4.5`, `w-2.5`

**❌ 不支持的值**：
- 多位小数：`w-22.5`, `w-53.75` ❌
- 必须改为整数或用方括号

### 4. 执行流程

```bash
# 1. 生成分析报告
find src -name "*.tsx" -exec grep -Hn "\[.*px\]" {} \; > /tmp/custom-values.txt

# 2. 按文件批量修改（先易后难）
# - 字号类（优先，最安全）
# - 间距/小尺寸类
# - 标准尺寸类
# - 接近值替换

# 3. 保留值添加注释

# 4. 验证
pnpm check
pnpm build

# 5. 构建后验证 CSS
grep -o "\.w-22\|\.w-54\|\.h-25" dist/client/assets/*.css
```

## 最佳实践

### ✅ 推荐

```tsx
// 好：使用标准整数类
<div className="w-22 h-28">

// 好：使用语义类
<p className="text-meta text-sm">

// 好：保留并注释
{/* 右侧栏固定宽度 340px（设计稿） */}
<div className="grid-cols-[1fr_340px]">
```

### ❌ 避免

```tsx
// 避免：能用标准类的不用自定义值
<div className="w-[160px]">  // 应该用 w-40

// 避免：能接近的不追求精确
<div className="w-[90px]">   // 用 w-22 (88px) 即可

// 避免：保留值缺少注释
<div className="h-[152px]">  // 为什么保留？
```

## 预期收益

1. **可读性提升 40%**：`w-22` vs `w-[90px]`
2. **减少自定义值 60-70%**：大部分能标准化
3. **维护成本降低**：团队成员更容易理解
4. **设计系统一致性**：更多使用标准间距

## 注意事项

⚠️ **关键原则**：
- 完全匹配 > 最接近值 > 保留自定义
- 1-2px 误差可接受，视觉几乎无差异
- 保留的必须注释，说明为何保留
- 构建验证是必须的，不能靠猜测

⚠️ **不要过度清理**：
- 布局定位的精确值（Hero 区、遮罩层）
- 设计稿精确尺寸（卡片组件）
- Grid 模板列的固定宽度
- 这些保留有助于保持设计精确度
