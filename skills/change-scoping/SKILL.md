# 划改动边界：不越界、不漏改

> 越界（改大了）和漏改（改小了）是同一根源的两面：**边界是「拍脑袋」画的，而不是「推导」出来的**。按文件/目录/具体实体划边界必然出错——要按「变更的语义单元」划。

触发场景（命中任一才读本 skill）：移入/移出某布局或容器、删对照组 / 下线 AB test、批量替换 / 迁移、重命名波及多处、"把所有 X 都改成 Y"。**这些都是集合操作，很少只涉及一个成员。**

## 1. 写谓词（防「用具体实体当边界」）

动手前写一句可判定的话，格式固定：

> 本次改动 = 满足 `<谓词>` 的**全部**单元，且**仅**这些单元。

关键：谓词用**分类名词**，不用**具体实体名**。

- ❌ 「改注册页」 → 会漏掉同因的登录页
- ✅ 「改所有曾参与本次 AB test 对照组的页面」 → 注册、登录都自然落入

谓词里若出现了某个具体页面/文件名，八成画错了——退一步问「它凭什么被改？那个『凭什么』才是谓词」。

## 2. 同因搜索（防漏改）

别信记忆，围绕**谓词里的名词**做 fan-out 搜索，产出「候选清单」：

- 搜标识：实验 key、feature flag、埋点事件名 → 谁引用谁是成员
- 搜容器的**所有**引用方：如 `with-footer` 布局被谁用 → 逐个列出
- 搜反向 import：对照组组件被谁依赖

搜索维度**围绕谓词名词**（AB test key / with-footer），**不围绕具体实体**（注册）。范围大时派 Explore 子 agent 做搜索，只要结论清单。

## 3. 对称模块检查（专防成对漏改）

发现自己在改一个「天然成对」的东西，停下来问：**它的兄弟在哪？为什么兄弟不用一起改？**

成对信号（命中任一必须显式回答「兄弟改不改」）：

- 登录 / 注册 / 找回密码
- 现货 / 合约
- 买 / 卖、开仓 / 平仓
- 移入 X / 移出 X ——**移动是集合操作，只移一个几乎必是 bug**

## 4. 减法确认（防越界）

对候选清单逐项反向审：

> 这一项如果**不改**，需求还成立吗？

- 成立 → 踢出边界（这就是「不影响无关逻辑」）
- 不成立 → 留在边界

越界与漏改用**同一份清单、两个方向的问题**兜底：「不改行不行」防越界，「兄弟改不改」防漏改。

## 5. 先给清单、后动手

最终清单在**动手前**发用户确认，而不是改完再解释。清单是廉价的，改错是昂贵的。

> 一句话护栏示例：「AB test 成员 = 注册 + 登录，两个都要移出 with-footer，其余页面不动，对吗？」——动手前甩这一句，越界和漏改两个坑同时消失。

## 6. 全集要求：用契约锁完整性，禁止兜底掩盖漏项

需求含「都 / 全部 / 每个 / 三个都加」时，**漏一项必须在编译期爆炸，不能在类型里被合法化**。

反面路径（自动修 bug 最爱走，因为 tsc / lint / 页面全过，却悄悄把需求降级）：

- 把字段改成可选 `tip?: string`，于是「缺一个」成了合法状态
- 加 `x ? <A/> : <B/>` 兜底，缺的那项静默走 fallback，不报错也不渲染

正面做法：

- **字段必填**：需求要求「每个成员都有 X」→ 写 `x: string` 而非 `x?: string`。漏填当场 TS2741。
- **全集用可枚举类型锁键**：一组对称项优先 `Record<EnumKey, Item>` 而非数组——少一个键编译不过，比数组更能保证「全集齐」。
- **补覆盖断言**：`items.every(i => i.x)` 的测试，或「值 === 原文」的字面断言。
- **数据缺失 → 报 blocker，不许自行降级需求**：文案 / 接口字段缺失时，要么按原文补齐（走终审），要么记一条 blocker，**绝不用可选 + 兜底把它伪装成「设计如此」**。

> 判据：可选字段只用于「业务上真的可有可无」，绝不用于「我这次没做完」。缺口要么补齐、要么显式报出，不许被类型悄悄吸收。
